## What the binder and readers do

- C v2's `NAMED_ONLY` becomes a fixed `KEYWORD_ONLY` slot. `NAMED_VARIADIC` becomes `VAR_KEYWORD`, with no typed option schema created. The C v2 signature API exposes parameter addition and return-type assignment. The internal C helper preserves an existing typed schema when it reorders slots. [C v2 implementation](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/main/capi/v2/capi_v2_func_signature.cpp#L6-L57) · [Signature helper](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/include/duckdb/main/capi/capi_function_signature.hpp#L62-L78)
- A fixed slot participates in overload matching and type checks. The binder rejects a missing required slot, adds the declared default for an omitted optional slot, casts the argument to the resolved type, and puts it in `named_parameters`. A typed kwarg is an optional name/type/alias entry. The binder validates it after selecting an overload and applies explicit-cast semantics. An omitted typed kwarg produces no map entry. On v2.0.1, `PlaceArguments` reaches the wrapper's typed schema for `encoding` and emits the invalid named parameter error before dispatch to the wrapper. Main has the equivalent failure in `FoldArguments`. [v2.0.1 binder](https://github.com/duckdb/duckdb/blob/8d78114e90a53823803660bf821f6073ac87da8c/src/function/function_binder.cpp#L554-L607) · [Main overload matching](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/function/function_binder.cpp#L375-L415) · [Main folding and casting](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/function/function_binder.cpp#L774-L911) · [Typed kwargs contract](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/include/duckdb/function/function.hpp#L232-L266)
- `MultiFileReader::AddParameters` declares shared options such as `filename`, `union_by_name`, and `allow_empty` as typed kwargs. CSV declares `encoding` and `types` through `ReadCSVAddNamedParameters`, with omission handled by `CSVReaderOptions`. JSON uses `JSONScan::TableFunctionDefaults` and `AddReadJSONParameters` to declare options such as `ignore_errors` and `columns`. Parquet supplies options such as `binary_as_string` through `AddNamedParameters` and adds `bound_schema` on the wrapper. These declarations explain why existing built-ins work with the typed-schema merge. [Shared options](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/common/multi_file/multi_file_reader.cpp#L120-L141) · [CSV](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/function/table/read_csv.cpp#L60-L109) · [JSON](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/extension/json/json_scan.cpp#L123-L153) · [Parquet](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/extension/parquet/parquet_multi_file_info.cpp#L253-L291)
- After SQL binding, `MultiFileBindInterface` currently tries the generic parser first. `TableFunctionMultiFileWrapper::GetDeclaredOption` already resolves an inner named-only slot or typed option, and `ParseNamedParameter` stores the value under the declared name. `TableFunctionFileReader::BindFunction` copies the argument map, invokes `FillNamedDefaults`, and binds the reader for that file. That path already handles the callback handoff. The public C header promises forwarding of declared named parameters. [Dispatch](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/include/duckdb/common/multi_file/multi_file_function.hpp#L250-L286) · [Reader lookup](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/common/multi_file/table_function_multi_file.cpp#L458-L497) · [Per-file bind](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/common/multi_file/table_function_multi_file.cpp#L79-L101) · [v2.0.1 header contract](https://github.com/duckdb/duckdb/blob/8d78114e90a53823803660bf821f6073ac87da8c/src/include/duckdb_v2.h#L14700-L14717)

## Recommended fix

**Copy the inner `KEYWORD_ONLY` entries as fixed slots in `TableFunctionMultiFileWrapper::CreateFunction`.** Preserve the name, type, declaration order, and optional default by copying the `FunctionParameter` object. Insert the slots before the wrapper's existing variadic options slot and retain its typed schema. `CV2MultiFileFunction::Build` already calls `CreateFunctionSet`, which clones the complete signature and varies argument zero for `VARCHAR`, `ANY[]`, and `VARIANT`. One signature change covers all three and the same C++ wrapper path. [C API build](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/main/capi/v2/capi_v2_func_table.cpp#L1330-L1358) · [Overload construction](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/common/multi_file/multi_file_reader.cpp#L1001-L1019)

Reserve the advertised shared option names and the wrapper's own slot names. Reject a case-insensitive collision at wrapper registration with the offending name. `TypedKwargs::Find` includes aliases, and `FunctionSignature::Verify` already rejects a named slot shadowing a typed option. Allowing duplicate declarations would be ambiguous. Silently dropping a colliding inner slot would hide the loss of a required argument or would keep passing its default while callers changed the wrapper option. Registration rejection is a deliberate behavior change for previously registerable wrappers with unreachable named slots such as `filename`. [Schema lookup and verification](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/function/function.cpp#L48-L85) · [Signature verification](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/function/function.cpp#L381-L465)

Sketch for `src/common/multi_file/table_function_multi_file.cpp`, immediately after the existing typed-kwargs merge in `CreateFunction`. It uses the established signature rebuild pattern and leaves the legacy typed-only path as it is. [Insertion site](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/common/multi_file/table_function_multi_file.cpp#L923-L945) · [Existing rebuild pattern](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/include/duckdb/main/capi/capi_function_signature.hpp#L62-L78)

```cpp
auto parameters = signature.GetParameters();
D_ASSERT(!parameters.empty() && parameters.back().GetKind() == FunctionParameterKind::VAR_KEYWORD);
auto options_parameter = parameters.back();
parameters.pop_back();
auto options = signature.GetTypedKwargs();
D_ASSERT(options);
const auto original_parameter_count = parameters.size();

for (const auto &parameter : wrapped_signature.GetParameters()) {
	if (parameter.GetKind() != FunctionParameterKind::KEYWORD_ONLY) {
		continue;
	}
	const auto &parameter_name = parameter.GetName();
	if (options->Find(parameter_name) || parameter_name == options_parameter.GetName() ||
	    parameter_name == parameters.front().GetName() || parameter_name == "paths") {
		throw InvalidInputException("Multi-file wrapper cannot forward reserved parameter %s", parameter_name);
	}
	parameters.push_back(parameter);
}
if (parameters.size() != original_parameter_count) {
	FunctionSignature wrapper_signature(std::move(parameters), signature.GetReturnType());
	wrapper_signature.AddTypedKwargs(options_parameter.GetName(), *options);
	wrapper_signature.Verify();
	signature = std::move(wrapper_signature);
}
```

### Alternatives

- **Project fixed slots into typed kwargs.** This is a shorter patch for optional options such as `encoding`. Add name/type with `ExtendTypedKwargs` and leave omitted defaults to `FillNamedDefaults` at per-file bind. The typed schema cannot represent a required slot or a default, and it changes argument casting and overload participation. A missing required argument could reach the per-file callback missing its slot. Prefer fixed slots for parity with direct calls. [Typed schema](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/include/duckdb/function/function.hpp#L247-L266) · [Per-file default filling](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/function/function.cpp#L354-L379)
- **Expose a new C v2 typed-kwargs setter.** Useful separately for authors who specifically want a closed option schema with aliases and omission handled by their reader. It would require defining the relationship with `NAMED_VARIADIC`, duplicate and alias validation, and the C-owned/borrowed value contract. It would touch `api_spec/v2/function/signature.yaml`, `capi_v2_func_signature.cpp`, generated API headers and extension tables, tests, and Rust bindings. Add it as an opt-in unstable API on `main` if pursued. Existing `NAMED_ONLY` declarations would still have the wrapper bug. The engine checks exact version metadata for `C_STRUCT_UNSTABLE`, and the v2 header guards unstable interfaces. [Signature spec](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/api_spec/v2/function/signature.yaml#L37-L119) · [Lifecycle rules](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/api_spec/v2/metadata.yaml#L1-L13) · [Extension version check](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/main/extension.cpp#L46-L73)
- **Accept undeclared names or move reader options into the file argument.** Untyped forwarding would shift validation past overload binding and weaken typo errors and discovery. File structs can carry separate per-file metadata when the inner file argument is `ANY`, but require a different SQL call and reader contract. Keep the fix in the wrapper's signature. [Binder validation](https://github.com/duckdb/duckdb/blob/87d96b7773a10356b11cc15c352125acdc58a9ce/src/function/function_binder.cpp#L843-L889) · [File argument contract](https://github.com/duckdb/duckdb/blob/8d78114e90a53823803660bf821f6073ac87da8c/src/include/duckdb_v2.h#L14700-L14717)

## Contribution and Rust follow-through

Target `main` for the engine bug fix. A v2.0.x backport is reasonable because the defect is present at the v2.0.1 tag, the forwarding contract is already public, and the fix requires no ABI addition. Maintainers have been backporting merged main fixes using the `backport v2.0-cyanoptera` label. Treat a new signature API as a separate main-branch feature. `CONTRIBUTING.md` asks outside contributors to discuss the change, keep it small, run fork CI before opening a ready PR, and add a regression. It specifies tabs, a 120-column limit, clang-format 11.0.1 and `make format-fix`. Run focused tests with `make unit T='[capi_v2][table_function]'` and `make unit T='test/extension/load_extension_capi_v2.test'`, then `make unit` and `make allunit`. I found no CLA requirement in the contribution guide or inspected public checks. ## Effort and risks

Estimate **1–2 engineering days** for the engine change, the C regression, and focused verification. Budget **another half to one day** for loadable SQL coverage and v2.0 adaptation if requested, plus CI and review time. A new typed-kwargs API would be a multi-day feature across the engine and Rust, with a separate API design review. The main review decisions are the collision policy for existing registrations, generic parser precedence for parser-only names, and C API overload selection when newly supported required named slots are present. Verify requiredness, defaults, explicit NULL, and `ANY` values across the generated overloads. The patch is source-level and leaves the per-file bind machinery in place. Verify CSV, JSON, and Parquet because they share that wrapper. No DuckDB build or test run was performed for this research.
